# Blog authoring

These components are used by **two** screens with the same code:

| Screen        | Route            | `scope`      | API prefix           |
| ------------- | ---------------- | ------------ | -------------------- |
| Academy blog  | `/website/blog`  | `'academy'`  | `/articles`          |
| Platform blog | `/platform/blog` | `'platform'` | `/platform/articles` |

`scope` only picks the API prefix (`apiClient.blogBase`). It never carries a
tenant id — the backend derives the academy from the JWT for the academy blog,
and hardcodes "platform" for the other. A wrong `scope` therefore cannot leak
one blog into the other; it just calls the wrong endpoint and gets a 403.

## Data flow

```
BlogScreen ──uses──> useArticles(scope) ──> apiClient ──> backend
    │                       │
    │                       └── refresh() after every transition, so the list
    │                           always shows the status the server actually has
    └──renders──> ArticleList ──> ArticleWorkflowActions
```

The editor screens (`ArticleEditorScreen` → `ArticleForm`) load and save one
article; they do not share state with the list, which refetches on return.

## Workflow

`DRAFT → IN_REVIEW → PUBLISHED → ARCHIVED`, defined in
`Backend/src/articles/article.constants.ts`.

`ArticleWorkflowActions` shows only the steps that are legal from the current
status, and hides approve/reject/archive from anyone who is not a manager or
platform owner. **This is a convenience, not a control** — the server checks
both the transition and the role on every call, and an illegal one returns
400 or 403 no matter what the UI offered.

## Slugs

The slug is generated by the backend from the title (Persian-aware, with a
`-2`, `-3` suffix on collision) and shown read-only. There is deliberately no
slug field: one rule server-side beats two implementations that can disagree.

## Content format

`TiptapEditor` produces **HTML**, which is what `Article.content` stores and
what edusphere renders through `SafeHtml`. Nothing is converted in between.
The older `MarkdownEditor` (used by course descriptions and site pages) emits
Markdown instead — the two are not interchangeable.
